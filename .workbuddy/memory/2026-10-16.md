## 修复 Illegal mix of collations 报错（11:30 前后）
- 现象：客户端单物料进出仓提交时弹 "Illegal mix of collations (utf8mb4_0900_ai_ci,IMPLICIT) and (utf8mb4_unicode_ci,IMPLICIT) for operation '='"。
- 根因（实测确认）：CREATE DATABASE 指定了 utf8mb4_unicode_ci → 存储过程字符串参数继承 unicode_ci；但三张表只写 DEFAULT CHARSET=utf8mb4 → 列用 MySQL 8 默认 utf8mb4_0900_ai_ci。SP 内 mat_code = p_mat_code 即冲突。MySQL 规则备忘：表只写 CHARSET 不写 COLLATE 时用字符集默认排序规则；SP 参数继承建库时的库排序规则；JSON_TABLE 字符串列默认 0900_ai_ci。
- 修复（不丢数据）：ALTER DATABASE warehouse COLLATE utf8mb4_0900_ai_ci + 用原脚本 89~287 行重建 3 个存储过程（参数随之继承 0900_ai_ci）。表不用动。
- 验证：CALL 三个 SP 用不存在物料/空明细测试，均返回正确业务报错（45000 SIGNAL），无 collation 错误、无脏数据。warehouse_inout 当时为空表。
- 同步修改 仓库管理系统_数据库设计.sql：CREATE DATABASE 改为 0900_ai_ci，3 张表加显式 COLLATE=utf8mb4_0900_ai_ci，头部加警示注释。今后整体重导脚本也不会复发。
- 环境更正：MySQL Server 8.4 在 PATH（C:/Program Files\MySQL\MySQL Server 8.4\bin\mysql.exe）；db.properties 密码为 root/123456（与 2026-10-10 日志记录一致）。

## 修复多物料进出仓"存在物料代码不存在"（11:50）
